## PASS и проверка

Различимы мелкий отбор, стандартное хранение, тяжёлый груз, длинномер и FLEX

Локальные критерии до построения плана:
1. Изолированный parseable proposal в принятой оболочке 144×72 м, Y up, метры; все прямоугольники положительные и не пересекаются внутренностями. Сумма площадей равна площади пола; классы площади показаны раздельно.
2. SMALL/STANDARD/HEAVY/LONG/FLEX имеют по две западную/восточную области; separation измерена. FLEX ограничен собственным footprint и предварительно только малым/стандартным грузом, вне circulation.
3. Защищены широкие peripheral approaches всех шести исходных port coordinates, связные cross/spine bands и южный проход. Receiving/shipping staging отделены от clear approaches; зарезервирован южный workspace под light conveyor и ровно шесть packing stations без их размещения.
4. Независимая 1 м occupancy-проверка сверяет суммарную площадь и отсутствие пересечений, flood fill проверяет связность clear floor и покрытие port approach rectangles. Это геометрическая проверка, не runtime route graph или proof of loaded-vehicle clearance.
5. SVG строится из JSON с масштабом, осями, точными границами, legend и явными reserved bands; фактически открыт. Краткий MD объясняет выбранные offsets относительно R07/R08 и ограничения.
6. Никаких slot counts/capacities, rack/asset placements, port service anchors/resources, route graph generation или L03. Evidence expected/actual и hashes; VERIFY до отдельного root image/artifact review.

Метод: фактический файл, измерение/расчёт либо meaningful runtime test по конкретному результату. Скрипт/export/отчёт исполнителя сам по себе не закрывает gate.
