`workerRoles.ts` exports `WORKER_ROLE_DEFINITIONS`, `WorkerRole`, `createWorkerInstance(template, actorId, role)`, `applyWorkerRole`, `resetWorkerRole`, `disposeWorkerInstance` и re-export `createWorkerRolesFixture`. Instance имеет readonly `root/actorId/role/disposed`; роли меняются через функцию, actorId остаётся прежним. `root.name=actor__{actorId}`, `userData.actorId` хранится отдельно от `roleCode`.

Только `V3_Worker_RoleVest` и `V3_Worker_RoleHeadwear` клонируются на каждого actor. Тела/rig geometry и остальные материалы разделяются как immutable resources. Исходный picker-ink скрывается только в клоне; новый extruded icon+code использует существующий shared ink material и одну owned geometry. Он ставится в frame исходного badge base, входит в него по глубине минимум1.5мм; actor ID в badge не запекается.

Role reset возвращает initial role, не меняя placement или текущую joint pose. Dispose освобождает только две owned material clones и owned badge geometry; shared template освобождает вызывающая сторона после всех instance. Повторный dispose безопасен; изменения disposed instance и некорректные role/actor/template явно отклоняются.

QA factory возвращает `{root,instances,reset,dispose}`. Root — `qa_worker_roles`, representative IDs P01/K01/R01/S01/F01 стоят через1.1м. Это пять сравниваемых QA экземпляров, не новая производственная численность; canonical24actors и WorkerProfile/RoleAssignment/seek staffing остаются за W15–W17.

`node tools/visual/v3/verify-worker-roles.mjs` загружает настоящий GLB через GLTFLoader и исполняет production TS modules после временной transpilation.
