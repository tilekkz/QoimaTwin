# Полное закрытие visual-ТЗ

Рабочая база опубликована в3f3da74. Полное visual-ТЗ ещё не закрыто; отсутствие backend не заменяет наши связные visual-сценарии.

Приоритеты:
1. Один общий workflow: исходная ячейка → допустимый захват → перенос → упаковка → отгрузка. Нужны реальные передачи одной HU, а не завершение по одному таймеру.
2. N0/N1/N2/N3 и шесть ворот: все материализованные заявки учитываются, ресурсы конечны, ожидания/отказы объясняются. Не каждая заявка обязана завершиться, если не хватает совместимой ёмкости.
3. N4: реальные переходы и смена role/color/badge исходных24работников в3D, возврат и сохранённая работа. Честный общий break-календарь A/B.
4. A/B: одинаковые входы, совместимость до стоимости, оплаченные обработка/пути/ожидания/возврат и допустимый no-op. Не объявлять визуальный пример результатом движка.
5. Итоговая QA: ориентации/handling/маршруты, replay/effects30×/60×,60секунд performance, обзор сюжета, независимое ревью и финальная поставка.

Сейчас добавлен общий экран scenario-v3.html: N0/N1/N2/N3(16/16/28/20заявок), исходные530HU и явно учтённые входящие, общие clock/ресурсы/маршруты, существующая native-паллета N2. Неподдерживаемый захват не считается выполненным. N4подключён к реальным3Dактёрам с уходом сменяемых упаковщиков на перерыв; выполняется проверка в браузере.

Идеальные углы локтей, дополнительные художественные детали и телефонная версия не входят в ближайшую работу. Исходный внешний вид персонажей сохраняется.
