## Refresh / retry action specification

| Aspect | Decision |
|---|---|
| Trigger/request | Manual refresh or retry, local read-only GET of registry JSON; no server mutation |
| Duration | Normally local/short;8s hard timeout |
| Pending | Immediate aria-busy/aria-disabled on focusable refresh; inline refresh status; first-load indicator after200ms and at least300ms once shown |
| Duplicates/races | UI ignores repeat while pending; programmatic replacement aborts previous request and checks monotonically increasing token |
| Optimism/idempotency | No optimistic success; GET safely repeatable with no side effects |
| Success | Validated24worker catalogue and successful-load time; query/role filter and expanded visible cards retained |
| Failure | Network/timeout/5xx allow manual retry;404or invalid data point to full package/model catalogue; last valid rows stay with stale label |
| Cancel/navigation | Leaving aborts fetch; no job/server work to roll back. No request lasts over8s. Query/filter are in URL, back navigation restores them; BFCache resume can reload safely |
| Server requirements | Only static local file serving; no new endpoint, backend role change, job ID or idempotency-key service |

No complex lifecycle diagram required for this read-only bounded GET. Filters run locally and do not issue requests. No uploads, queued writes or unsaved data.
