# C05 — type compatibility before placement cost

The [saved matrix](../../v3/contract-proposals/storage-compatibility-v3.json) contains40 concrete family cases and candidate sets projected onto all776 native C04 slots. Ten family cases are positive. There is no sixth reserve storage type: all188 blocked/reserve addresses retain their access rejection.

These candidate sets overlap the same physical slots; their counts are not independent capacity, stock or an assignment. Type acceptance intersects the C02 cargo family tags with each C04 slot's explicit allowed archetypes. A geometrically small item does not automatically gain another storage type.

The shared `storage_eligibility.evaluate()` resolves reserve access, type, declared proper upright orientation, exact `orientedDimensions + 2c <= usable`, per-HU payload, slot occupancy, module payload and an allowed available handler before any score. Missing, mirrored or unlisted rotation rejects. Dimensions use Decimal comparisons without an epsilon halo. Supported placement calls the accepted C04 helper: HU bottom equals support Y, zero hover; X is centred and Z front-aligned with the required clearance. Vertical clearance is allocated above the supported HU. FRAGILE's .95m height plus .10m budget exactly fills1.05m usable height; bottom .20/top1.15 leave .10m headroom.

The evaluator labels its result `design_eligible`, always with `operational_admission=false` and `cost_evaluated=false`. A positive design candidate does not prove actor availability, support/lock/contact geometry, a route, inventory conservation or source scheduling. W must compose those separate gates. The unchanged C02 template and C04 source hashes are bound in the artifact.

Run `.venv/Scripts/python.exe tools/visual/v3/storage_eligibility.py --check-only`. Thirteen distinct invalid cases cover wrong type/orientation/size, payload, unknown mass, occupied slot, module payload, bad occupancy, wrong/missing handler, reserve access, reflection and a1e-10m excess above the exact height budget. C06/C07 add orientation and mass-specific witnesses to this same evaluator. No alternative compatibility solver or shared/backend contract is introduced.
