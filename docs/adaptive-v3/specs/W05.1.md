# W05.1 — Source-bound visual action intervals and clock

This is a pure foundation for later scene joins. It uses the existing V3 fixture, 24 canonical actors/P11 profiles, all 16 accepted RoleClip records, 2 assigned vehicles, 6 real packing-post IDs, 530 initial HU identities and optionally the one W04 cart C01. It never moves a model, transfers stock, assigns a current role or completes a job. All outputs retain `source_kind:visual_fixture`, `engine_operation:false`, `operational_admission:false`, `physical_join:false`, `cost_evaluated:false`, `completed_jobs:0`.

## API and source registration

`await registerWarehouseActionCatalogue(bundle, readSource, holderCatalogue?)` requires a deeply immutable JSON-data bundle. A read-only iterative check rejects mutable descendants, cycles, accessors, functions (including a `toJSON` mask) and custom object/array prototypes before reading any source. It neither invokes getters nor freezes foreign input. A shallow-frozen clone is rejected even if its current JSON happens to match.

`readSource(path)` returns actual `Uint8Array` bytes. The factory rereads the four canonical base documents through the existing V3 adapter and compares their decoded content with this exact bundle. It verifies every existing registry source/proof hash. Durations, role, asset ID, prerequisites and accepted-task bindings come only from the validated 16 clips. The immutable result is issued through a private WeakMap and bound to the supplied bundle object for identity checks. Its private state retains the adapter's separate verified deeply immutable snapshot. Compilation reads the horizon, workers, profiles, HU identities and resources from that private snapshot; it does not read live caller-owned bundle descendants after issuance.

An optional issued W04 holder catalogue for that same bundle declares the cart only when its C01 upper-tote source matches the accepted support kit; the six support-kit source hashes are then verified. Without that catalogue, C01 remains explicitly unavailable. No caller-provided count, capacity, duration, asset or transform is accepted. Source reading is injected: this module does not fetch, open files or activate a backend itself. A future browser package must provide these exact source bytes or an explicitly reviewed replacement registration mechanism.

`compileWarehouseActionTimeline(bundle, catalogue, {timeline_id, actions})` returns typed admission plus `timeline` on success, or `timeline:null` and a friendly reason on rejection. Invalid batches cannot mutate an earlier timeline. Only issued catalogues for the identical bundle object are accepted.

Each action has exactly these fields:

```ts
{action_id, actor_id, clip_id, start_s, end_s, depends_on,
 vehicle_id, cart_id, post_id, handling_unit_id}
```

The four resource-reference fields are always present; unused references are `null`. Times are finite nonnegative seconds within the source 1800-second fixture horizon, on a microsecond grid. Intervals are half open `[start_s,end_s)` and have positive duration. Moving clips must use their exact source duration; static-pose clips may occupy an explicit interval while sampling local clip time zero. The maximum batch is 4096 intervals.

Every interval reserves its actual actor ID. Driver clips require that actor's assigned vehicle; picker walk/pick require C01; packer/receiver/shipper workcell clips require one of PK01–PK06. Payload actions require an existing initial HU ID for exclusive identity reservation. Optional HU reservation is also permitted for other clips. Every claimed actor, vehicle, cart, post and HU has finite capacity one. There are no synthetic pools that multiply staff or equipment. Adjacent reservations are legal, gaps release resources, and dependencies must form a DAG whose predecessors end before the dependent interval starts.

P01/P02 may pass the existing additional packer skill eligibility check; the output marks `role_transition_required:true` and retains skill .8. It does not assign that role or rescale an accepted clip's explanatory time. Physical travel, role transitions and skill-adjusted workflow service times remain later work.

## Absolute sample and events

The issued timeline exposes immutable `actions`, exclusive `calendars`, sorted `events`, `sample(t)` and `eventsBetween(from,to)`. Sampling clamps finite time to the timeline bounds and derives active intervals and local clip times directly; it has no accumulated scene state. End events sort before start events at a shared boundary. `events_at_time` is deterministic boundary metadata, not a one-shot cue stream.

`createWarehouseActionClock(timeline)` exposes `play`, `pause`, `setSpeed(0 < speed <= 60)`, `seek`, `reset`, `advance(realDeltaSeconds)`, `setTimeline`, `getState`, `getFrame`, `getTimeline`, and idempotent `dispose`. Only `advance` emits `crossed_events` for `(previousTime,newTime]`. Seek/reset/play/pause/speed changes and reads emit no historical cues. A boundary at time zero is visible in `sample(0)` but is not backfilled by a later advance. After an explicit rewind, a subsequent forward crossing may emit a future boundary again. The host supplies elapsed time; this module starts no RAF, timer, audio or renderer. Timeline replacement requires another issued timeline from the same exact catalogue and resets time without cues.

## Prerequisites that this foundation does not satisfy

The 16 source clips remain `warehouse_joined:false`, and their exact accepted prerequisite text is carried in each compiled row. Reserving a full HU identity does not equate the P03 four-unit partial pick with a complete C02 24-unit HU. Packer finishing does not perform carton forming or packing contents; receiver/shipper clips do not perform decoding, receipts or stock mutation. Driver pickup does not establish arbitrary loaded-route admission. Shared post reservation does not bind a source workcell to that physical station. Native support, loaded clearance, anchored action-frame joins, walking, complete-unit mapping, actual resource acquisition and role-transition motion need their own later acceptance.

## Verification

Run from `frontend`: `node tools/check-warehouse-action-timeline-v3.mjs` and `node tools/check-warehouse-action-timeline-v3.mjs --check-only`. The gate checks real accepted sources, all 16 clips, canonical counts, half-open boundaries, overlap/gap/dependency negatives, stale/unissued/mutated input rejection, shallow and partially frozen input rejection without foreign freezing, accessor/prototype/cycle refusal, post-issuance horizon/resource/profile mutation protection, absence of live original-bundle reads during compilation, absolute clock seeks, exact-once forward end cues, speed changes and conserved stock/actor identities. Typecheck/build remain the root's integration checks.
