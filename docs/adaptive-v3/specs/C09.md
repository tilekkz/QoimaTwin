# C09 — Совместимость перед стоимостью

`tools/visual/v3/admission_policy.py` разрешает только **проектного кандидата** SKU→slot. Входы — неизменяемые C03/C02, C04, L12, C08v0.2 и две объявленные пары F01/FL01, F02/FL02. Все шесть SHA сохранены в `admission-policy-v3.json`. Shared/backend contracts не менялись.

Запрос содержит только `sku_id`, `slot_id`, optional `orientation_id` и `transport_tag`. Массу, размеры, scale или содержимое заменить через запрос нельзя. Engine-owned `PlanningContext` содержит исходный node, направление, проектные equipment tags, занятые места, массу модулей и недоступные arcs. Это snapshot планирования, не реальная бронь сотрудника или техники.

Порядок фиксирован: canonical identity → C05 тип/ориентация/точные размеры/масса/вместимость/handler → equipment и обе C08 rating positions → разрешение порта → существование пути в отфильтрованном направленном графе → **только после всех gates** Dijkstra по физическим метрам и один placement-score callback. Unweighted BFS отвечает только на существование пути. Отказ возвращает reason и `cost_evaluated=false`; невозможному кандидату невозможно присвоить выгодную стоимость через callback.

Для manual используются `pedestrian`/`manual_cart` arcs и соответствующий worker/cart target; для forklift — nominal pair, cargo whitelist, local/main profiles, width/height и неизменённый load. Inbound идёт origin→slot, outbound slot→origin. Default cost — метры одного плеча, не длительность заказа, throughput или экономия. Custom callback обязан вернуть конечное неотрицательное число; NaN/bool/negative даёт `INVALID_SCORE` уже после eligibility.

Положительный ответ всегда сохраняет `planning_only=true`, `operational_admission=false`, `actual_mesh_actions_verified=false`. Он явно требует фактические M/P support/contact/retention/lock/action и runtime reservations/staging/traffic. Аналитические признаки не подставляются вместо настоящего подтверждения замков или опор. Реальный DES/backend результат не заявлен.

Reachability и shortest paths кэшируются по frozen graph kind, cargo, mode, pair, blocked-arc set и обоим node IDs. Live occupancy/module/handler/port gates проходят заново перед обращением к кэшу. Возвращаемые dimensions и arc IDs копируются; изменение ответа вызывающим кодом не меняет canonical cargo или будущие пути.

Проверено восемь неизменённых классов HU и 94 отрицательных случая: запрещённая подмена массы/scale, orientation, отсутствие handler/equipment, занятый slot, module overload, неизвестный origin, полностью закрытые пути, неверная pair/type и reserve. Во всех отказах score callback вызван **0 раз**. Восемь NaN-score случаев отклонены после ровно одного вызова. Независимый root probe проверил 16 реальных направленных inbound/outbound paths, непрерывность arc IDs, режимы/pairs/profiles и сумму длин. Ещё 37 guards заменяли weighted-route и callback функцией, которая немедленно падает: ни один отказ её не достиг.
