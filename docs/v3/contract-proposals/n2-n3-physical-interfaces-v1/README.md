# N2/N3: физические интерфейсы для API

Этот отдельный V3 namespace передаёт точные системы координат, опоры, контакты, состояния креплений и условия стыковки. Арман может использовать его для реализации API и проверок входных данных. Старые `contracts/**`, V2 и исходный C08 не меняются. Наличие геометрии не является выполненным складским действием: планировщик, ресурсы, фактические события и непрерывные действия требуют своего подтверждения.

## Файлы

| Файл | Назначение |
|---|---|
| `bundle.json` | Версия пакета, SHA секций и исходников |
| `n2-staging.json` | Три целые HU, native-опоры M03, два конечных места приёмки, высоты вил и контактов |
| `n3-retention.json` | Рамы LONG/cradle, нижние штифты, верхние прижимы, фиксаторы и отдельная стойка снятой оснастки |
| `route-terminal-interfaces.json` | Исходные ID графа/портов, терминальные позы, новые явно предложенные связи и причины отказов |
| `n3-current-input.json`, `n3-current-pair.json` | Текущие source refs и одинаковые входные байты baseline/adaptive |
| `n3-input-migration.json`, `n3-historical-*.json` | Полный metadata diff и сохранённые прежние источники; физических изменений нет |
| `n2-relative-pi-endpoints.json`, `n3-relative-pi-addon.json` | Отдельные предложенные варианты сохранения world-позы HU при относительном yaw=π |
| `retention-api.d.ts` | Типы абсолютной позы и запроса перехода крепления |
| `retention-prototype.mjs` | Чистый расчёт рам; подготовка запроса без выполнения операции |

Система координат правосторонняя, +Y вверх; длины в метрах, время в секундах, масса в килограммах, углы в радианах. Quaternion имеет порядок xyzw. Масштаб каждого объекта — 1. Координата HU — исходный pivot модели, а не произвольно выбранный центр габарита.

## N3: LONG и оснастка

Одна исходная LONG HU: 4.20×0.52×0.65 м, 200 кг, 24 единицы. Cradle вместе с верхней оснасткой — 40 кг; общая поднимаемая масса — 240 кг. При транспортной высоте вил Y=0.75 cradle pivot в раме погрузчика равен `[0,0.65,1]`, pivot HU — `[0,0.80,1]`. Четыре нижние опоры в раме cradle: `(±1.4,0.15,±0.2)`.

Нижние штифты имеют native Y-ход 0…0.11 м. Верхние прижимы открываются вокруг X до −80°. Четыре фиксатора сначала выводятся наружу по X на 0.35 м. Направление последующего извлечения зависит от явно указанной рамы; локальный −Z нельзя заменять world +Z без учёта yaw.

Отдельная предложенная стойка имеет две исходные опоры M03 `[26.6,0,14]` и `[29.4,0,14]`; pivot верхней оснастки `[28,0.07,14]`. Вместимость — одна оснастка, **0 HU**. Эти экземпляры и два staging-места являются явным дополнением к конфигурации; они ещё не выдаются за уже выполненную перестановку Scene или приход товара.

## Стыки и выполнение

Сначала проверяются source hashes, ID, физическая рама груза, профиль, опоры и все условия перехода. При attach сохраняется фактическая world-поза той же HU; нельзя подменять исходную ориентацию значением identity. Поворот погрузчика вместе с закреплённым грузом отличается от изменения относительного поворота груза.

Статический исторический тест LONG с разными yaw погрузчика и HU не доказывает непрерывный подхват с относительным yaw=0. Новый вариант относительного yaw должен выбираться явно и иметь отдельное доказательство. Неподтверждённые источник/профиль/траектория/ресурс дают конкретный отказ, а не автоматический разворот, телепорт или выполненную операцию.

`prepareRetentionEvent` возвращает невыполненный запрос. Истинные времена, доступность F01/FL01 или F02/FL02, action-space, traffic и изменения authoritative ledger остаются на стороне интеграции. Существующие 24 работника, 2 погрузчика и количество товара не увеличиваются геометрическим пакетом.

## Проверка

Из корня репозитория, Python из окружения проекта с `jsonschema` (на этой Windows-машине `.venv/Scripts/python.exe`):

```text
python tools/visual/v3/freeze_n2_n3_interfaces_v3.py --check-only
python tools/visual/v3/verify_n2_n3_interfaces_v3.py --negative-controls
```

Валидатор читает исходный BIN GLB самостоятельно, проверяет конечные треугольники и контактные нормали, исходные HU/массы/размеры, контактные рамы, конечную вместимость, графовые стыки и SHA пакета. Проверки не изменяют исходники и не запускают backend.

Текущий `retention-prototype.mjs` реализует только основной вариант relative-yaw=0. Он явно отклоняет запрос нового π-варианта. Данные π-варианта и доказательства сохранения исходной world-позы переданы для отдельного явного подключения потребителем; непрерывное действие ими не подменяется.

Для получения файлов Арману достаточно обновить `origin/codex/twin-v3-adaptive` и начать с `bundle.json`. Пакет не требует переноса старых рабочих каталогов `work/` и не записывает принятие интерфейса backend-потребителем.
