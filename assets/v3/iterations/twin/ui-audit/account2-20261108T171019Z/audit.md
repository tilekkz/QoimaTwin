## Findings

**TWIN-A2-001 · Medium — worker bubbles lose click targets and retain old causes.** In `frontend/src/adaptive-v3/twin/twinRender.ts:188`, hiding deletes `dataset.actor` but keeps `dataset.key`. Line 190 restores the actor only if the actor/reaction-kind key changes; the installed click handler at line 117 requires the actor. Effects off/on at fixed time therefore restores a visible, unclickable bubble; zoom out/in can take the same path. The key also omits reaction text, so B's 46-second PK05 cause update (`twinScenario.ts:58`) leaves a same-kind wait bubble's accessible label on the earlier PK03 cause. Expected: current actor/text on every visible bubble. **Executed WHITE_BOX COMPONENT_ONLY:** exact AST-extracted domFor and installed click callback, real scenario samplers, synthetic W1 worker, DOM and projection/scale. No renderer. Both failures reproduced.

**TWIN-A2-002 · Medium — reload keeps the card but drops renderer/list selection.** `frontend/src/adaptive-v3/twin/twinPage.ts:259` destroys the twin without clearing selected ID/kind or closing/rebuilding its card. The replacement twin starts unselected (`twinRender.ts:47-48`); ready initialization (`twinPage.ts:278`) never reapplies selection. Select a moved HU, then Retry following context loss (`:287`), or restore a persisted page: the previous card and page selected ID can remain while scene/list highlights are absent. Expected: clear selection or validate/restore it. **Executed COMPONENT_ONLY:** actual load/dispose helpers; synthetic source/adapter/twin/scene/navigation, pre-existing selected-card fixture and stubbed UI helpers. HU1 remained selected in page state while the replacement twin had null selection. Actual rendered recovery and changed reload data were not executed. URL present=1 separately clears selection through presenter start.

**TWIN-A2-003 · Low — clicker forward cannot finish the last step.** `frontend/src/adaptive-v3/twin/twinPage.ts:175` sends PageDown/ArrowRight to goStep(index+1), which clamps to the last index (`:105`). The final Next button exits instead (`:116`). Step 8 repeats and stays open with the key, but closes with Finish. Expected: consistent final forward completion. **Executed COMPONENT_ONLY:** real goStep/endPresent and installed event callbacks; downstream time/mode/camera/selection/sheet functions were recording stubs. Sixteen forward/back/reentrant step applications restored configured arguments. NaN to the private debug API throws; no normal UI producer was found, so it is not a product finding. No pre-presentation state restoration promise was found.

**TWIN-A2-004 · Low — activated sound lacks visibility/pagehide cleanup.** `frontend/src/adaptive-v3/twin/twinPage.ts:56-61` resumes audio and schedules voices; lifecycle handlers (`:298-299`) stop visual playback without muting/suspending/closing audio or stopping voices. A queued note can outlive the hidden/stopped view to its scheduled stop, approximately 0.6 seconds maximum for current cues, subject to browser behavior. Expected: explicit pending-cue silence and context lifecycle policy. **Inferred exact-source finding; no browser/audio-hardware execution.** No claim of indefinite sound.
